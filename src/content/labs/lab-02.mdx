### The hook details you will need in a real app

`useEffect` runs after React draws the screen. Its dependency array controls when it runs:

| You write | It runs |
| --- | --- |
| `useEffect(fn)` | after every render |
| `useEffect(fn, [])` | once, after the first render |
| `useEffect(fn, [query])` | after the first render and whenever `query` changes |
| `return () => ...` inside `fn` | before the effect runs again and when the component unmounts |

```tsx title="Load data when a screen opens"
const [movies, setMovies] = useState<Movie[]>([]);
const [loading, setLoading] = useState(true);

useEffect(() => {
  fetch('https://example.com/movies.json')
    .then((response) => response.json())
    .then(setMovies)
    .finally(() => setLoading(false));
}, []);
```

`useRef` returns a box whose `.current` value survives renders. Attach it to an input when you need to focus that input, or use it for a value that should not redraw the screen.

```tsx title="Focus the title when validation fails"
const titleRef = useRef<TextInput>(null);

function save() {
  if (!title.trim()) {
    titleRef.current?.focus();
    return;
  }
}

<TextInput ref={titleRef} value={title} onChangeText={setTitle} />
```

`useMemo` remembers the result of a calculation until one of its inputs changes. It is useful for filtering a large list, but ordinary small calculations do not need it.

```tsx title="Filter only when movies or query changes"
const filteredMovies = useMemo(
  () => movies.filter((movie) => movie.title.toLowerCase().includes(query.toLowerCase())),
  [movies, query],
);
```

> [!IMPORTANT]
> Call hooks only at the top level of a component or custom hook. Never put a hook inside an `if`, loop, event handler, or nested function.

### Conditions, lists and stable keys

Use a ternary when exactly one of two things should appear, and `&&` when something is optional:

```tsx
{loading ? <ActivityIndicator /> : <MovieList movies={movies} />}
{error && <Text className="text-red-600">{error}</Text>}
```

When `.map()` creates components, each outer element needs a unique, stable key. Do not use the array index when items can be inserted, removed or reordered.

```tsx
{movies.map((movie) => <MovieCard key={movie.id} movie={movie} />)}
```

### One more idea: function props

A child can’t change the parent’s state — but the parent can **give it a function** to call.

```tsx title="App.tsx → ContactCard.tsx"
// parent (App): owns the state, passes a function down
<ContactCard name={c.name} favourite={favs.includes(c.id)} onToggle={() => toggle(c.id)} />

// child (ContactCard): calls it when tapped
<Pressable onPress={onToggle}><Text>{favourite ? '★' : '☆'}</Text></Pressable>
```

<Task n="10.2" title="Dynamic routes and route parameters" time="6 min">

Square brackets create a dynamic page. `app/recipe/[id].tsx` handles `/recipe/1`, `/recipe/2`, and every other recipe id.

```tsx title="app/recipe/[id].tsx"
import { Stack, useLocalSearchParams } from 'expo-router';

export default function RecipeDetails() {
  const { id } = useLocalSearchParams<{ id: string }>();
  const recipe = recipes.find((item) => item.id === id);

  if (!recipe) return <Text>Recipe not found</Text>;

  return (
    <View>
      <Stack.Screen options={{ title: recipe.title }} />
      <Text>{recipe.title}</Text>
    </View>
  );
}
```

> [!WARNING]
> Route parameters are strings. If your data uses numeric ids, compare with `item.id === Number(id)`.

<Task n="10.3" title="Share state between pages with Context" time="7 min">

The Details page changes favorites, while the Favorites tab displays them. State owned by either page would disappear from the other, so place it in a provider **above both screens**.

```tsx title="context/recipes.tsx (short version)"
type RecipesValue = {
  favorites: string[];
  toggleFavorite: (id: string) => void;
};

const RecipesContext = createContext<RecipesValue | null>(null);

export function RecipesProvider({ children }: PropsWithChildren) {
  const [favorites, setFavorites] = useState<string[]>([]);
  const toggleFavorite = (id: string) =>
    setFavorites((current) =>
      current.includes(id) ? current.filter((item) => item !== id) : [...current, id],
    );

  return <RecipesContext.Provider value={{ favorites, toggleFavorite }}>{children}</RecipesContext.Provider>;
}

export function useRecipes() {
  const value = useContext(RecipesContext);
  if (!value) throw new Error('useRecipes must be inside RecipesProvider');
  return value;
}
```

Wrap the Stack with `<RecipesProvider>` in `app/_layout.tsx`. Any screen below it can then call `useRecipes()`.

  - problem: '"Text strings must be rendered within a <Text> component"'
    cause: Text was placed directly inside a View.
    solution: 'Wrap every piece of text in `<Text>…</Text>`.'
  - problem: '"Each child in a list should have a unique key prop"'
    cause: 'A `.map()` returns items without a `key`.'
    solution: 'Add `key={item.id}` to the outer element, or use `keyExtractor` on a FlatList.'
  - problem: '"Too many re-renders"'
    cause: 'The state is set while rendering, e.g. `onPress={setCount(1)}` calls it immediately.'
    solution: 'Pass a function instead: `onPress={() => setCount(1)}`.'
  - problem: '"Rendered more hooks than during the previous render"'

<Task n="1.2" title="What is React?" time="4 min">

React is a JavaScript library (made by Meta) for building user interfaces. You describe **what** the screen should look like for the current data, and React works out **how** to update it.

You build the screen from **components**: small, reusable pieces, each with its own look and logic, nested like boxes:

<Task n="1.3" title="Function vs class components" time="3 min">

Old React code uses **classes**. Since React 16.8, **function components + hooks** do the same job with less code, and that is all we write in this course.

```tsx title="Class component (old style — just recognise it)"
class Counter extends React.Component {
  state = { count: 0 };
  render() {
    return <Text onPress={() => this.setState({ count: this.state.count + 1 })}>{this.state.count}</Text>;
  }
}
```

```tsx title="Function component + hook (what we write)"
function Counter() {
  const [count, setCount] = useState(0);
  return <Text onPress={() => setCount(count + 1)}>{count}</Text>;
}
```

</Task>

<Task n="2.2" title="Components & props" time="8 min">

A component is a **function that returns UI**. **Props** are its arguments: data passed from the parent, read-only inside the child.

```tsx {1,8}
function Greeting({ name }: { name: string }) {   // receives the prop
  return <Text>Hello, {name}!</Text>;
}

export default function App() {
  return (
    <View>
      <Greeting name="Mariam" />                    {/* passes the prop */}
      <Greeting name="Omar" />
    </View>
  );
}
```

<Task n="3.2" title="useState + events" time="12 min">

<Explain parts={[
  ['const [count, setCount]', 'the current value + the function that changes it'],
  ['= useState', 'the hook'],
  ['(0)', 'the starting value'],
]} />

- Calling `setCount(5)` stores the new value **and redraws** the component.
- Never change state directly (`count++` does nothing on screen). For arrays and objects, make a **new** one: `[...todos, newTodo]`.
- When the new value depends on the old one, use the updater: `setCount((c) => c + 1)`.
- Events take a **function**: `onPress={() => setCount(count + 1)}`, not `onPress={setCount(count + 1)}`.

<Task n="3.3" title="useEffect" time="12 min">

`useEffect` runs code **after** the screen is drawn: the place for timers, fetching data and subscriptions (what class components did in `componentDidMount`, `componentDidUpdate` and `componentWillUnmount`).

| You write | It runs |
| --- | --- |
| `useEffect(fn)` | after **every** render (rarely what you want) |
| `useEffect(fn, [])` | **once**, after the first render |
| `useEffect(fn, [query])` | after the first render, then whenever `query` changes |
| `return () => …` inside `fn` | the **cleanup**: before the next run, and when the component leaves the screen |

<Playground ex="demo-use-effect" demo />

<Playground ex="e07-stopwatch" />

The most common use: load data when the screen opens.

```tsx title="Fetching data (you'll do this in a later lab)"
const [movies, setMovies] = useState<Movie[]>([]);
const [loading, setLoading] = useState(true);

useEffect(() => {
  fetch('https://example.com/movies.json')
    .then((res) => res.json())
    .then((data) => setMovies(data))
    .finally(() => setLoading(false));
}, []); // [] → only once, when the screen opens
```

</Task>

Square brackets make a **dynamic** page: `app/recipe/[id].tsx` opens for `/recipe/1`, `/recipe/2`… and reads the value with `useLocalSearchParams`:

<Explain parts={[

<Task n="5.3" title="Sharing state between pages" time="5 min">

Favorites are set on the Details page but shown on the Favorites page. The state must live **above** both, in a **Context**:

```tsx title="context/recipes.tsx (short version)"
const RecipesContext = createContext(null);              // 1. the shared box

export function RecipesProvider({ children }) {           // 2. owns the state
  const [favorites, setFavorites] = useState<string[]>([]);
  return <RecipesContext.Provider value={{ favorites, setFavorites }}>{children}</RecipesContext.Provider>;
}

export const useRecipes = () => useContext(RecipesContext); // 3. any page reads it
```

Wrap the app with `<RecipesProvider>` in `app/_layout.tsx`, then call `useRecipes()` in any page.

</Task>
